# segurança, 31/08/2026). Antes deste commit só `bcrypt` tinha pin e todo o
# resto flutuava para o mais recente no momento do `docker build` — ou seja, a

# release quebrada (ou comprometida) de qualquer dependência entrava em
# produção sem revisão.

# ⚠️ Este arquivo declara o que o projeto USA. O que a imagem INSTALA é o
# `requirements.lock`, que fixa também as transitivas — pin de direta sozinho
# não fecha o buraco, porque a maior parte da árvore é transitiva (15 diretas,
# 60 pacotes instalados).
#
# Para atualizar uma dependência:
#   1. mude a versão aqui
#   2. pip install -r requirements.txt
#   3. pip freeze --exclude-editable | sort > requirements.lock
#   4. rode a suíte inteira ANTES de commitar

# ⚠️ bcrypt travado em <4.0 de propósito: passlib==1.7.4 (sem manutenção
# desde 2020) lê `bcrypt.__about__.__version__` pra detectar a versão do
# backend, atributo removido no bcrypt 4.x. Sem este pin, hash_password()
# quebra com um ValueError enganoso ("password cannot be longer than 72
# bytes") mesmo pra senha curta. Confirmado no Minotto em 20/08/2026.
#
# ⚠️ Dívida conhecida (auditoria 31/08/2026): é o passlib sem manutenção que
# obriga a manter crypto de 2022. Trocar passlib por bcrypt puro ou argon2
# libera este pin. Fora do escopo daquela sessão de correções.
